# 演进历史

## 1. 最简单的情况
首先最简单的就是：输入 -> LLM -> 输出

## 2. 赋予动作
我们遇到了什么问题：LLM无法作出发邮件，阅读文件等动作。
我们期望的流程：输入 -> LLM -> 调用工具 -> 工具结果送回LLM（不断循环，直到模型认为解决完毕了问题） -> 输出
我们怎么操作：告诉LLM我们有什么函数（send_email, read_file），让模型输出要调用的工具，以及参数 (read_file {"path": "~/README.md"})

## 3. 状态保存
### 失败恢复
我们遇到了什么问题：
1. 每次送给LLM的只有调用API时传入的内容，LLM不保存内容，每次要全量传递过去，不会帮我们维护之前对话过什么
2. 多步骤任务中，无法了解当前运行到第几步了，而且中断了无法继续跑（例如：总共要调用 10 次模型，调用到第 5 次的时候失败了，前面白费了）
- 失败恢复，以及了解当前任务进度，因此，需要把执行过程中每一步保存下来，输入，输出，成功与否，当作持久化内容，即：**状态**。
- 链路追踪，（没有的话，用户问了个问题，中间经历了 10 个步骤，系统得到一个答案，如果答案不符合预期，想要知道到底是哪一步出错了，目前无法得知。）

## 4. 链路追踪

因此，需要使用一个 TraceId 串联起来整个链路。每个小步骤都用节点记录。TraceId -> (SpanId1(用户输入) -> SpanId2(数据库检索到的知识) -> SpanId3(调用LLM))
